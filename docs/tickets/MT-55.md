# MT-55 — Adaptador gerado para skill com `invocacao: humano`

**Contexto.** A spec 0001 manda traduzir `invocacao: humano` para o mecanismo de cada harness:
`disable-model-invocation: true` no Claude Code, `policy.allow_implicit_invocation: false` no
Codex, aviso onde não houver mecanismo. O adaptador de skill hoje é symlink para o diretório
neutro, e symlink não carrega cabeçalho diferente por harness. A spec registrava os tickets
como "a criar"; este é o do instalador.

**Escopo** (ADR 0023 §6)

- Para skill com `invocacao: humano`, o adaptador vira diretório real: `SKILL.md` gerado com o
  cabeçalho traduzido e o corpo idêntico; os demais arquivos por symlink (ou cópia, em
  `--skills-mode copy`).
- Skill sem o campo, ou com `invocacao: modelo`, continua por symlink inteiro.
- Relatório por harness de quantas skills não puderam ser traduzidas (spec 0001, critério 6),
  entrando na matriz de lacunas do MT-53.
- `--update` regenera o `SKILL.md` gerado quando o neutro muda.

**Critério de aceite.** Os critérios 1 a 3 e 6 da spec 0001, no `testar-instalador.sh`, com uma
skill fabricada `invocacao: humano` instalada para `claude`, `codex` e um harness sem mecanismo.

**Spec.** [0001](../specs/0001-invocacao-declarada.md) · [0002](../specs/0002-instalacao-por-agente.md)

**Depende de.** MT-52, para saber para quais agentes gerar. Destrava o MT-45 e o MT-46, que
importam skills `invocacao: humano`.
