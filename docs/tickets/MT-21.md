# MT-21 — Contraparte da adoção de papéis: verificar **invocação**, não instalação

> **Revisado em 2026-10-07.** O ticket media a variável errada. Observado em uso real: 35
> subagentes nomeados instalados num projeto e **nenhuma invocação** em 5.936 chamadas de
> ferramenta — o critério de instalação passaria verde com uso zero. O aceite agora é taxa de
> invocação não-nula em sessões reais, separando agente genérico de agente nomeado. **Falha
> hoje, de propósito: essa falha é a informação.**

**Contexto.** A proposta de adoção de papéis nomeados
([`docs/interop/proposta-adocao-papeis.md`](../interop/proposta-adocao-papeis.md)) exige que o
carregador do outro projeto **recuse** papel cujo corpo pressuponha um harness indisponível.
Isso só é possível se o acervo declarar o que cada papel exige — entrega nossa, não deles.

**Escopo**

- Campo novo no frontmatter dos subagentes, com três valores: `nenhuma` (o corpo usa só as
  ferramentas mapeadas), `<harness>` (usa recurso específico) ou `desconhecida`.
- Preenchimento a partir da medição de portabilidade já existente.
- Verificador `checar-subagentes.py`: todo papel declara nível e dependência; `tools` só usa
  nomes do conjunto mapeado; nenhum papel traz nome de modelo ou de provedor.
- O verificador entra no CI, junto dos outros autotestes.

**Critério de aceite.** O verificador reprova um papel construído de propósito com dependência
não declarada e outro com ferramenta fora do conjunto; passa no acervo real; roda no CI.

**Dependência.** A declaração é útil mesmo se a adoção for recusada — ela documenta o que cada
papel exige para funcionar, que hoje só existe como medição agregada.

**Fora de escopo.** Reescrever corpo de papel para remover dependência. Declarar não é
converter.
