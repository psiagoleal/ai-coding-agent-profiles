# MT-13 — Verificador de links de Markdown, versionado

**Contexto.** Outra sessão relatou ter escrito um verificador de links *ad hoc* em Python
**três vezes na mesma semana**, descartando-o ao fim de cada turno. É o padrão que a skill
`licoes-aprendidas` chama de parar abaixo do nível viável: cabia um comando versionado com
passo no CI, e ficou no gesto manual. Nossos próprios painéis e ADRs dependem de link que
resolve — a skill `micro-ticket-planner` diz que "link quebrado é painel mentindo", e hoje
nada confere isso.

**Escopo**

- Verificar links relativos de arquivos Markdown: destino existe e, havendo âncora, o
  cabeçalho correspondente existe.
- Cobrir `docs/`, `skills/` e a raiz; ignorar o que estiver no `.gitignore`.
- Saída legível (arquivo, linha, link), código 0/1, sem dependência externa.
- Link externo (http) fica fora por padrão: exige rede, torna o gate instável.

**Critério de aceite.** Roda no repositório do framework e aponta zero falso positivo;
introduzir um link quebrado de propósito faz o comando sair com 1; entra como passo do CI.

**Fora de escopo.** Verificação de links externos, correção automática e renomeação de
arquivos. Mudança de escopo vira ticket novo.

**Limitação declarada.** A regra de âncora implementada é a do GitHub (minúsculas, acento
preservado, sufixo `-1` em cabeçalho repetido). Renderizadores como o mdBook geram âncora
própria; num repositório publicado por eles, o verificador vira alarme falso e precisa de
`--excluir` ou de outra regra.

**Entregue.** `skills/pr-review-guard/scripts/checar-links.py` — 73 arquivos do framework
conferidos, 0 problema, depois de corrigir um link realmente quebrado em `docs/refs/`.
